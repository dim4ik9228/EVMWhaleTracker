# Separate runtime settings from secrets

- Status: completed
- Date: 2026-10-29
- Summary: use appsettings for ordinary runtime configuration, secrets-only dotenv for Docker, then deploy with existing settings preserved and all supported EVM chains enabled.

## Requirements

User requests regeneration from User Secrets and deployment of passwordless billing, plus moving non-secrets out of the large dotenv. Implement this refactor before deployment. Public defaults belong in appsettings.json; Development overrides apply only in Development. Use an optional Git-ignored appsettings.Local.json for deployment-specific non-secret settings, including private operator IDs/contact/URLs, mounted read-only into the app and loaded in Production too. Preserve environment override precedence. No real IDs/endpoints with embedded credentials in committed files/images.

Dotenv should contain only Telegram token, provider API/IPN secrets and credential-bearing DB/RPC values actually needed. Docker topology/environment name/loopback ports can remain declarative Compose configuration; ordinary switches/limits/URLs/chain identities should not be mirrored through dozens of environment variables. Runtime settings and secrets must not leak in command output or Docker build context. Correctly quote arbitrary secret characters; reject multiline values. Preserve shared and per-network RPC key overrides and avoid placeholders overriding appsettings defaults. No Google/dashboard credentials.

Preserve effective live HL/PM enabled flags, network endpoint settings, limits, operator allowlist, billing sales/enforcement disabled, database volume/password/connection, wallet settings and protocol enrolments. Enable BSC, Base, Arbitrum, Ethereum and Robinhood (all currently supported EVM chains); Polygon is the separate PM adapter and must remain enabled as currently configured. Arc stays removed, native scanning disabled. Never recreate the DB with a new password or reset persisted data. Capture private baseline/current effective container configuration before mutating dotenv; migrate ordinary effective settings into private JSON before exporting secrets. Do not use stale User Secrets non-secret values to disable current functionality or enable sales.
