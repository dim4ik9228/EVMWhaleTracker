## Runtime design

Add an explicit default-off sandbox billing mode selecting only the fixed documented sandbox host; production remains the existing fixed host. No arbitrary provider URL accepting credentials. Sandbox runtime requires a separately named sandbox database, zero enabled EVM chains, HL/PM off, Stars sales off, an explicit operator allowlist, and only those operators may use sandbox checkout. Mark Telegram views/notices prominently SANDBOX / NO REAL PAYMENT. New isolated orders retain normal USD29/720-hour snapshots (simulated funds); do not change production pricing.

Preserve hosted `/invoice` flow. For simulation, use the documented sandbox `/invoice-payment` endpoint with the actual invoice ID and allowlisted `case` (`success`, `failed`, `partially_paid`, optionally common), initiated by an operator-only test control or bounded helper. Verify any returned invoice checkout URL is sandbox-domain before opening it; never auto-open a production checkout returned by stale sandbox code. Production build never submits `case` or simulation requests when sandbox mode is off.

Provide nonbinding sandbox-only terms text endpoint with explicit no-money/test-data wording, and support explanation. It must return unavailable outside sandbox. Make the tunnel allow exact callback POST plus sandbox terms GET during testing only; public health stays blocked. Explicitly label test terms as nonbinding rather than publish invented merchant purchase terms. Retain callback HMAC-SHA512, API-key status verification, frozen quote, invoice/order binding, exact owner and one grant per order. If sandbox omits required fields or reports incompatible network/state, report limitation; do not fabricate identifiers or amounts to pass.

Optional Compose sandbox service(s) use a dedicated PostgreSQL volume/database, app image, loopback HTTP8081, separate ignored settings/secrets and existing Docker network. Do not mount normal appsettings.Local into sandbox or copy wallet/user ledger records into it. A fixture-safe exporter may map BillingSandbox API/IPN keys and the existing Telegram token to sandbox-only private env files; output no values, keep ordinary switches in sandbox JSON, exclude all private files from Git/image/publish. Do not place sandbox credentials into production .env or modify production merchant setup.
